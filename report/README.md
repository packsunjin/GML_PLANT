# 결과보고서 빌드

한글(HWP) 서식2 규칙에 맞춘 결과보고서를 **HTML 원고 → DOCX**로 만드는 도구입니다.
한글이 외부에서 수정한 HWPX 파일을 거부하는 문제가 있어, DOCX 로 만들어 한글에서 열어 저장하는 방식을 씁니다.

## 원고를 고치고 다시 만들기

```bash
cd report
python parse2.py                 # tpl.html → blocks.json
python build_docx.py --compact   # 20쪽 판  (--compact 없이 돌리면 전체판)
python pagecount.py GML_결과보고서_20쪽판.docx
```

`tpl.html` 하나만 고치면 됩니다. 나머지는 거기서 파생됩니다.

## 서식 규칙 (원본 양식에서 확인한 값)

| 항목 | 값 |
|---|---|
| 전체 분량 | **20페이지 이내** — 양식 제목줄에 명시 |
| 본문 | 휴먼명조 **11pt** |
| 장 (Ⅰ, Ⅱ, Ⅲ) | 휴먼명조 14pt |
| 절 (1, 2, 3) | 휴먼명조 12pt |
| 항 (1), (2) · 목 ①, ② | 휴먼명조 11pt |
| 표 제목 | 표 **상단** 중앙, 휴먼명조 11pt |
| 그림 제목 | 그림 **아래** 중앙, 휴먼명조 11pt |
| 그림 해상도 | 300dpi 이상 |
| 줄간격 | 160% |

본문 11pt 는 양식이 못박은 값이라 분량을 줄이려고 낮추면 안 됩니다.
참고문헌만 9pt 로 두었습니다(양식이 참고문헌 크기는 지정하지 않았고, 양식 자체의 각주·미주 스타일이 9pt 입니다).

## pagecount.py — 쪽수 추정

이 환경에서는 LibreOffice 가 동작하지 않아 렌더링으로 쪽수를 셀 수 없습니다.
그래서 `document.xml` 을 직접 읽어 문단·표·그림 높이를 더해 추정합니다.
한글은 한 글자가 정확히 1em 폭이라 폭 계산은 잘 맞고, 남는 불확실성은 **폰트의 기본 줄상자 높이**입니다.

```
줄상자 1.10 → 18.5쪽      줄상자 1.25 → 20.5쪽
줄상자 1.20 → 19.9쪽      줄상자 1.30 → 21.0쪽
```

즉 **19~21쪽**으로 보면 되고, 정확한 값은 한글에서 열어 확인해야 합니다.
20쪽을 넘으면 아래 순서로 줄이는 것을 권합니다(뒤로 갈수록 잃는 정보가 큽니다).

1. 부록 `3. 용어 정리` — 이미 20쪽 판에서 빠짐
2. 표11(측정계 한계와 개선 방향) — Ⅳ장 6절 본문의 요약이라 사실 손실 없음
3. Ⅱ장 1절 (1) 역사 서술 첫 문단
4. Ⅳ장 6절 (5) 기준전극 분극 문단

## renumber.py — 표·그림 번호 다시 매기기

표나 그림을 넣고 빼면 번호가 어긋납니다. 문서 등장 순서대로 다시 매깁니다.

```bash
python renumber.py            # 미리보기
python renumber.py --write    # 적용
```

안내상자의 예약 번호(`■ … · 표5`)도 번호를 차지하는 것으로 세며, 본문의 참조도 함께 고칩니다.
두 번 돌려서 "바뀌는 번호 없음"이 나오면 정합한 상태입니다.
